# 人工与程序质量门 —— Member-A 真实历史反例驱动

参照 `ProfessorZhi/example-session-repo` 的 `MEMBER_A_INTERVENTION_MAP.md` / `MEMBER_A_TAKEOVER_SCORECARD.md`、MarketOps 正式 SOP；本插件**不复制**真实会话中的客户邮箱、原始 11 GB 语料或访问凭据。

## 基础规则

1. **能抓到 ≠ 事实可信**。搜索摘要只是 `discovered`；网页 200/OK 如果正文是 WAF/CAPTCHA，也属于 `blocked`。
2. **有数据 ≠ 已落库**。验收对每个阶段检查真实非空行、行数、主键唯一、外键、来源哈希与被舍弃行，并作 `input→output→HOLD` 对账。
3. **一站可能有多个场地**。不能按 hostname 去重全部场地；一个组织可能运营多块场地，关联必须带责任类型。
4. **候选人 ≠ 正式联系人**。过期岗位要重查；邮件必须从抓到的页面中实际出现，搜索 snippet 不能作为邮箱证据；电话/网页表单是 Signal 不是 A/B/C/D 邮件联系路线。
5. **双轴判断**：`account_assessments.decision` 是某 Scene 的客户资格，`contact_routes.grade` 是可联系路线等级；一个不能推出另一个。
6. **未知 ≠ 零 / 不存在**。脚本和报告都要区分 `unknown`、`hold`、`blocked`、空输入、无数据、没有检查。
7. **变更需版本**。Brief、SOP、审核标准与成本限额的变化必须可追溯。数据包不是多进程数据库，禁止两个 Agent 同时写入一个 CSV。
8. **审查者不能凭状态自证成功**。一个 `ready` 必须有可回读的来源内容、邮箱字面证据与已记录人工审查，不能只检查一格布尔值。
9. **Excel 特别风险**。来自网络的任何字符串都必须当文本，避免注入 `=HYPERLINK(...)` 或其他公式；保留以零开头的 ID 和邮编。透视表及图表数字以真实非空源行计算。
10. **费用和访问**。Skill 不构成服务端预算硬门；自动充值、网页登录、绕过 CAPTCHA、表单提交、发送和无限定时任务一律不在 v0.2 授权内。

## 人工审查前的停止条件

- 目标地区/客户类型与已批准 Brief 冲突；
- 预算、授权或 Provider 认证不存在；
- 仅获取到挑战页、目录站标题、机器生成的猜测结论；
- 机构归属不明、两份资料相互矛盾、人员现职无法核实；
- 用户要求将未经验证的邮箱写成 `ready`，或要求研究插件执行外联动作。

遇到上述条件，应写入 `review_queue.csv` 并输出明确 blocker，不要假装整个调研成功。

## 与 MarketOps 真正后端的边界

本地数据包仅用于小规模试用和跨客户端文件交接。正式多用户任务要使用 MarketOps 已经定义的 Workspace/Scene/Run/WorkItem/Evidence/ContactRoute 授权；不得靠复制 SQLite 或上传整包到任意云盘“实现同步”。

下次交接时保留：用户原始目标、政策版本、源 URL、原始页 hash、各阶段实际行数/状态、未解决项、已批准费用、停止原因。
