# MarketOps Research Assistant 0.7.6

调研插件：从公开数据集到场地池、机构池，再到带证据、已评级的联系人，最后交付一张 Excel。
给 Claude Code 用。插件只提供能力，流程由 agent 自己掌握。

## 装

```bash
./install.sh            # Linux / macOS。Windows 用 Install.ps1
```

安装器做三件事：
- 建私有 Python 环境 `~/.marketops/venv`；
- 装 Crawl4AI 用的本地浏览器；
- 逐个询问五把密钥（Serper、SerpApi、DeepSeek、TinyFish、Jev），存到 `~/.marketops/keys.env`，只有本人可读。

然后在 Claude Code 里：

```
/plugin marketplace add ProfessorZhi/marketops
/plugin install marketops-research-assistant@marketops
```

## 用

直接说任务，或者用 `/marketops-research-assistant:research 瑞士户外天然草足球场，找场地负责人`。

插件 = MCP 工具 + 三个 skill：`marketops-research`（工作流：五个池子 数据源 → 页面 → 场地 → 机构 → 联系人，多 agent 流水线）、`marketops-tools`（六个工具怎么用、缺了怎么降级）、`marketops-knowledge`（Bruce 业务经验和常见卡点）。主 agent 用宿主自己的多智能体模式（Claude Code 子代理、Codex agent、WorkBuddy 多智能体）把找源、挖源、官网、调研、收尾几组 worker 同时开起来，各段并行，同一段里多个 agent 各自认领；脚本是团队手里的批量工具。Codex 和 WorkBuddy 的接法见 [HOSTS.md](HOSTS.md)。

| 工具 | 做什么 |
|---|---|
| `project` | 建立或打开项目文件夹，保存简报，查看进度（`flow`：各池大小、池子之间积压、各队列的 agent、对账）、成本和余额 |
| `sources` | 数据源池：找到名录就登记，看每个源的状态（找到 / 在挖 / 已读完 / 已入池 / 放弃）、带来了多少、是否饱和 |
| `harvest` | 挖一个数据源：翻名录分页或读 sitemap，批量并发读条目页，每页一行候选（名称、类型、官网、邮箱、电话、地址），Jev 从页面外链里挑官网 |
| `search` | Serper、SerpApi、DeepSeek、TinyFish 四路同时搜，按网址合并；`maps=True` 查地图地点 |
| `pool` | 从下载的开放数据文件建场地池和机构池：过滤、改列名、按运营方归并成机构 |
| `fetch` | Crawl4AI、TinyFish、DeepSeek 三路同时读同一页，每份都保存，联系人取并集；数据文件直接下载 |
| `browse` | 后台用 TinyFish Agent 处理需要点击才能看到内容的难站 |
| `judge` | Jev 对任意池子逐行回答一个选择题，例如是否在范围内、是不是官网 |
| `grade` | Jev 按简报评 A/B/C/D/X，不分语言；agent 也可以手工改 |
| `run` | agent 的批量读站工具：`run(orgs=[…])` 后台读完一包机构的官网（找站、读高价值页和 PDF、抽取、评级）交回给 agent；不带 `orgs` 时只替调研 worker 提前读站，不深挖、不建池，领先 30 家没人接就暂停，1 小时没有 agent 接活就结束 |
| `tasks` | 共享任务队列：主 agent 把缺口机构、待复核、难站、数据源切成任务包，多个 worker 并行认领、完成、交回；agent 拿着的机构流水线不碰；`verdict` 记每家的结论 |
| `orgs` | 每家机构一份摘要（扫到了什么、待复核、找法手册、结论），按阶段筛选；`set` 改官网、分类、范围 |
| `export` | 导出 Excel（指标口径写明、分批、待复核标记）和 Bruce 的 18 列路线 CSV |

项目文件夹就是普通文件（`~/MarketOps/<项目>/`）：`brief.json`、`venues.csv`、`orgs.csv`、
`contacts/`、`crawl.csv`、`trace.jsonl`、`costs.jsonl`；网页原件在共享资料库 `~/.marketops/library`。agent 和人都可以直接打开、修改，断了接着跑。

## 0.7.6 更新：密钥槽位不再有上限

- **槽位不设上限**：`SERPER_API_KEY`、`SERPER_API_KEY_2` … `_N`，设了多少个编号就认多少个槽，`_10`、`_25` 都算，编号按数值排序（`_10` 在 `_9` 之后）。一个值里用逗号分隔多把仍然可以。之前写死到 `_9`，第 10 把静默不生效。

## 0.7.5 更新：名录采集不再造假机构、重复机构自动找出、交付前必须抽检（巴黎 11 区 0.7.4 复盘）

- **`harvest` 去掉名录站的外壳**：同一来源大多数条目页共有的名字（"Haut"、"回到顶部"这类导航）换成条目自己的标题或小标题；大多数条目共有的邮箱（名录方页脚自己的邮箱）不再记到每一条上；结果里用 `chrome_removed` 说明。列表页读了却一条也没抽到，会返回 `warning`（通常是 `follow` 写错了），不再当成空来源。0.7.4 那轮 188 行里有 181 行名字是 "Haut"，邮箱都是名录方的。
- **入池按行绑定邮箱**：行里自己带的邮箱一定入池；只有一行来自的详情页才把整页地址并进来，同一页出来多行的是名录，页上的其他地址不再摊给每一家。之前已保存过的页会让入池跳过行里自己的邮箱。
- **合并后不再"复活"**：已合并的机构再入池同名时，并到保留的那家。
- **重复机构自动找出**：括号里的缩写、XI 和 11、11e 和 11ème、错一个字母、一个名字包含另一个名字（只有这两家共有的词）、同名不同写法的城市，都会列进 `flow.possible_duplicates`，重叠的配对合成一组。0.7.4 那轮 15 行手工合并的，现在都能自动找出。
- **项目刚开始不会误报收工**：还没有任何来源和机构，或上游还有人拿着任务时，认领返回 `keep_waiting`。
- **试点低于 5% 的来源默认暂停**：按 Bruce 的规则自动暂停，worker 不再等主 agent 裁决；`needs_you` 列出来，主 agent 用 `scale` 恢复。
- **官网核对更严（各国通用）**：自动找官网时，域名要带上机构名一半以上的词，或带一个只有它有的词、且搜索结果里有它的城市；名录站自己的首页不当条目的官网；域名里看不出机构名的官网，摘要里有 `website_check` 提醒研究员核对。
- **自动解开 ROT13 邮箱**：不执行页面脚本的读取器会拿到编码后的地址（如 `@tznvy.pbz`），现在自动还原。
- **人名、职位字段清洗**："Président : 姓名, 邮箱" 这类整句会拆成职位和人名，去掉邮箱、电话、网址。
- **交付闸门**：工作簿第一行"交付状态"，确认的 A/B 至少抽检 20 条（不足 20 条的全抽）且准确率 ≥90% 才写"可交付"；`export()` 返回 `delivery`，`needs_you` 会一直提醒到抽检做完。
- **标准测试**：简报去掉不可执行的数量上限；团队改为主 agent + 找源、入池、调研三个 worker。

## 0.7.4 更新：不空转、名录不误挂、重复机构可合并（巴黎 11 区与法国 41 省对照复盘）

- **通道空了不等于收工**：认领为空时说明原因——`keep_waiting`（上游还在找源、挖源，继续用 `wait=50` 认领）、`other_lanes`（别的通道有活）、`why_empty`（试点中、来源暂停，或 brief 的 `max_per_source` 已到上限，还有多少家没读）；只有 `lane_finished` 才收工。还有活却空了，会进 `needs_you` 提醒主 agent。`tasks(status)` 也带同样的说明。巴黎 11 区那轮三个 worker 读到 `open: 0` 就停了，310 家没读，主 agent 13 分钟后才发现。
- **列表页不再整页挂到一家**：一页印着 6 个以上别人的邮箱就是名录（在机构自己的站上，要路径像 `/associations`、`/annuaire`，或超过 25 个）；带 `org_id` 读这种页，只有写着这家名字的那一条和它自己域名的邮箱归它，其余记入 `unattributed.csv`，`fetch` 返回 `list_page`，提示把这页登记成来源、把条目作为新机构入池。41 省一个市镇的 `/associations` 页曾把 76 个协会邮箱挂到市镇名下。俱乐部自己的理事会页照常全给它。
- **重复机构可合并**：同名词、同登记号、同一个个人邮箱的两家，列在 `flow.possible_duplicates` 和 `needs_you`，不再被当成连锁；`orgs(merge=[{keep, drop}])` 把联系人、结论和空字段并过去，被并的那行留作 `merged_into`，来源对账照样成立。严格账同一个邮箱只算一次。
- **brief 改为合并更新**：`project(brief=...)` 只改传入的键，`null` 删除一个键。之前只传一个键会把 goal、region、fresh 全抹掉。
- **暂扣的名录地址不计入总数**：超过 60 条被暂扣的地址单独一张表，不进任何总数；agent 用 `grade(held=[{org_id, held: "X"}])` 清掉（或 `"grade"` 交给 Jev）。
- **官网核对**：自动找官网时，搜索结果里的邮编都不在本机构所在省份，就不用（41 省的 Verdigny 曾配到 Cher 省的同名市镇）；演出目录、企业名录网站（sortiraparis、societe.com、pappers 等）不再当官网。
- **抽检进流程**：确认的 A/B 有 10 条以上还没抽检时，`needs_you` 会提醒；交付前至少核对 20 条。
- **和 Bruce 同口径的指标**：工作簿和复盘里新增"有确认 A+B 的机构 ÷ 有任一 A–D 路线的机构"（Bruce 法国 71/249 = 28.5% 就是这个口径）和"已研究机构中有确认 A+B 的占比"。`stages.dig` 的等待数和 dig 通道一致。

## 0.7.3 更新：每个来源都轮到、名单里的邮箱不再丢（巴黎 072 复盘）

插件增强 agent，不替 agent 做决定：下面每一条都是默认行为，agent 都能改。
- **来源轮流 + 试点**：`sweep` / `dig` / `site` 三条队列按来源轮流派活，每个来源先给 30 家试点，A/B ≥5% 才继续给；低于 5% 的来源暂停，并在 `needs_you` 里说明。主 agent 用 `sources(set=[{source, status: "scale"}])` 放量、`"dropped"` 停掉。072 入池 27 个来源，40 分钟里 4 个调研 agent 只做了第一个。
- **名单里的邮箱直接成为联系人**：学校名录、俱乐部名单、场地时段表这类每行带邮箱的文件，入池时邮箱就挂到这一行的机构上，引文是这一行，照常评级。072 丢了 1,658 个以上。可以映射 `email` / `person` / `role`。
- **登记号识别机构**：UAI、SIRET、RNA、SIREN 优先于名字+城市；城市只有邮编时不当城市用（072 里 744 组重名）。法国开放数据的 `;` 分隔 CSV 按表头识别。`harvest` 采到没有标题的页面也会补上名字（072 一份文件 176 行只剩 3 行）。`replace_operator=True`：后来的来源更清楚谁在运营场馆时，可以改写运营方。
- **从零模式**：brief 写 `"fresh": true` 后，不复用别的项目读过的页面、搜索和经验；不是本项目抓取、采集或登记过的文件入池时，会标成"外部带入"。产品默认仍然复用，更省钱。
- **TinyFish 付费 Agent 默认关闭**：`browse` 先记下页面，`needs_you` 一次性问用户；brief 里写 `paid_agent: true` 才执行。
- **工具调用日志**：每次工具调用都记进 `calls.jsonl`（哪个 agent、哪个工具、参数摘要、耗时、错误），不看对话原文也能复盘完整链路。
- **快速测试题**：巴黎 11 区，从零开始，约 1 小时（`references/benchmarks.md`）。

## 0.7.2 更新：agent 主导，工具跟随（巴黎 071 审计修复）

- **脚本不再自己调研**：`run` 默认不深挖（`rounds` 默认 0，最多 2，且一轮没有新地址就停）；不带 `orgs` 时只提前读站，读完 30 家没人接就暂停，`project()` 的 `needs_you` 会提示开调研 worker，1 小时没有 agent 接活就结束；自动找源（`discover`）默认关闭，建池是找源和挖源 agent 的工作。`dig` 队列会自动补充：调研 worker 认领时，拿到的是工具读过但还没有确认 A/B 的机构。
- **邮箱只归给页面绑定的那家**：名录页、门户页上的邮箱，只有在同一块里写着这家机构名字时才归给它（引文末尾的"下一条"不算，并要求名字里最少见的那个词出现）；其余记入 `unattributed.csv`（追加写）。071 里 58% 的邮箱同时挂在 ≥3 家机构下，单个邮箱最多挂 66 家。A/B 没有职位的进复核。
- **不再把机器跑满**：同时处理的机构数、读页线程、浏览器标签、进程数都按本机 CPU 和内存（包括 cgroup 的 `memory.high`）自动设定。071 跑到 4,094/4,096 个线程，内存超过 `memory.high` 后所有进程停摆。线程不够时自动减半。
- **坏链接记忆**：所有读页器在 12 小时内对同一 URL 失败 2 次，就不再读它，读成功一次即清除。071 的失败读取里有 74.5% 落在已经失败过的 URL 上。
- **计数和崩溃**：机构失败时会正确离开在途计数，新增 `failed` 计数；数据文件和跳过的页面不再引发 `KeyError`。

## 0.7.1 更新：agent 做调研，工具可选，阶梯降级，会自我改进

- **超流水线建池子**：数据源 → 页面 → 场地 → 机构 → 联系人，每段一条认领队列，各段同时跑，同一段多个 agent 并发；找源和挖源分开，旧源在挖的同时新源一直在找。数据源池至少 3 个源、最近 3 个每个新增不到 5% 才算饱和，单一来源会一直报警。
- **skill 收成三个**：工作流、工具、Bruce 经验与卡点；角色说明每份一页；市场细节和基准题按需读。
- **agent 做调研**：主 agent 把机构按约 10 家一包分给调研 worker；每个 worker 从头做到尾：用工具一次读完这一包（`run(orgs=…, rounds=0)`，只读页、抽取、定级，不深挖），看摘要，自己深挖，逐家写结论。没有自己跑的后台进程；吞吐取决于开了几个调研 worker。原来的自动管线降为可选的"快速模式"。
- **每个工具都可选，按级降级**：`project()` 报告当前级别（full / reduced / minimal）、缺了什么、影响什么。
  - 没装 Crawl4AI 服务也能启动，读页由 TinyFish、DeepSeek，最后由纯 HTTP 兜底；
  - 没有搜索 key 时，提示 agent 改用宿主自带的网页搜索；
  - 没有 Jev 时，规则先判，其余由 agent 判。
- **多槽位 key**：五家供应商都能配多把 key（`NAME`、`NAME_2`…`_9`，或用逗号分隔）。欠费、额度用完、key 无效或到了红线，就自动切到下一把，用完的那把 6 小时后再试。key 文件（`keys.env`、`MARKETOPS_KEYS_FILE`）改了就生效，不用重启。
- **Jev 真正降本**：规则先判掉明显的行（本机构通用信箱判 D，明显不是这家的地址判 X），Jev 只判真正需要判断的。Jev 不可用时不再让每家机构白等。
- **搜索主力**：Serper 和 SerpApi（地位相同，额度用完时互相替代）加 DeepSeek，TinyFish 同时参与。
- **站点健康分**：死链和死站暂时搁置，会复活。一次失败不算数，要跨时间重复失败或两个读页器都失败才算；我们自己的网络或代理问题不计分；404 只记那一页；反爬只记那个读页器。
- **自我改进**：
  - 工作日志：agent 记卡点、顺畅处、决定和想法，插件也会自动记；
  - 导出时生成脱敏的 RETRO.md；
  - 跨项目知识库：找法手册按市场和机构类型沉淀，失效的自动降权；深挖搜索方法按效果排序。
- **修正**：
  - 门户上的通用页面不再算给几十家机构；
  - 列着多家机构的页面按名字算给对应的每一家；
  - `orgs(add=…)` 可以直接把找到的真正运营方加进池子；
  - 给 agent 的回复更精简（找法手册每次只附一份，去掉重复的链接列表）。
- **模拟**（agent 做调研，60 家，含脚本够不到的路线）：3 个调研 agent 并行，68/68 条路线，零误报，60 家每家都有结论。

## 0.7.0 更新：agent 团队分段协同

- 推动工作流的 skill 重写：主 agent 用宿主的多智能体模式开五组 worker（来源、建池、官网、挖掘、整理），五段同时推进，按 `project()` 的 `stages` 积压调人；脚本扫描是团队的第一遍，不是终点。各组职责在 `references/roles/`，三种宿主通用。
- 新工具 `orgs`：每家机构的摘要（agent 不用重读网页就能决定下一步），按阶段筛选，`set` 改官网、分类、范围。
- `run(orgs=[...], again=True)`：给 agent 用的批量扫描，后台跑，和主流水线并行。
- 找法手册（`project(name, playbook=...)`）：agent 总结某类机构的联系人在哪类页面、用什么搜索词、找什么岗位；脚本对这类机构先读这些页、先跑这些搜索。agent 研究一小批，脚本放大到整类。
- 并行安全：provider 限速全机共享（多个 agent 一起调也不会挤爆 429）；agent 领着的机构流水线先跳过；深挖任务只派流水线做完的机构。
- 页数按收益：页面还在出新地址就继续读（最多 40 页），名录翻页跟到底；连续两页没新东西才停。
- agent 结论（`tasks(action="verdict")`）和交付抽检（工作簿「抽检」页 100 条，`grade(set=[{..., checked}])` 记结果，说明页给准确率）。
- Codex、WorkBuddy 接入说明（HOSTS.md），安装器打印 Codex 配置片段；这两家要在真机上验证。
- 列着多家机构的页面（辖区、联合会、市镇联合体的页面）不再只算给第一家：同一页为另一家读时直接用存档重新解析，不发新请求，地址也算给这一家。

## 0.6.4 更新：先去掉白干的活和误拦，再提并发

依据：巴黎题实测（0.6.2）加两道题的离线模拟（假网络，读页、搜索、Jev 都有真实延迟）。

**提速**
- 读页"先到先用"：几家读取器同时读，最快的一家读到内容后最多再等 3 秒就往下走；慢的在后台读完，联系人照样补进来。搜索同理（慢引擎的结果进资料库）。每家读取器、每个搜索引擎各用自己的线程池，一家堵住不拖累别家。
- 找人名只查刚评出的 A/B 行，同一地址加同一段引文只问一次，多批并行（之前每轮把所有没名字的 A/B 重问一遍，规模越大越慢）。
- 同一地址加同一段引文只评一次，评过的直接复用；简报 `address_rules`（如 `{"info": "X"}`）在入库时就定级。
- 共用门户（一个域名挂 3 家以上机构）只读本机构那一页及其子页，不再整站爬。
- 各来源轮流进流水线；单进程默认同时 24 家（模拟里 12 → 24 吞吐翻倍，结果不变）。

**不再误拦**
- 只有纯通用信箱（info、contact、office……）直接判 D；secretariat、sports、service、mairie 这类岗位信箱交给 Jev，可以是 B 或 C。
- 他站页面（联合会、名录）上的 A/B，只要引文旁写着本机构名字，就计入头条，只是证据分低一些；不写名字的才标待复核。
- 共用地址挂 3 家以上机构才标待复核（一个市政体育处管两三块场地是常态）。
- 没有官网的机构先按名字和城市找一次官网（域名带名字，或首页标题是它的名字）。

**留痕**：每家机构在 `trace.jsonl` 记一行（各阶段秒数、联系人和 A/B 在哪一步出现）；工作簿"过程（耗时）"页按来源、阶段汇总。

**模拟结果**（法国场景 120 家，与本版第一个提交对比）：同样 12 路并发，每分钟 30.7 → 36.9 家，找到的 A/B 机构 47 → 62（共 62 家，零误报），其中俱乐部 5 → 20；默认改 24 路后约每分钟 77 家（240 家规模，127 家全部找到）。巴黎场景同样全部找到。消融：关掉深挖快一倍，但俱乐部的 A/B 少一半以上，保留。
