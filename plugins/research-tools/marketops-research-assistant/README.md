# MarketOps Research Assistant 0.7.1

调研插件：从公开数据集到场地池、机构池，再到带证据、已评级的联系人，最后交付一张 Excel。
给 Claude Code 用。插件只提供能力，流程由 agent 自己掌握。

## 装

```bash
./install.sh            # Linux / macOS。Windows 用 Install.ps1
```

安装器做三件事：
- 建私有 Python 环境 `~/.marketops/venv`；
- 装 Crawl4AI 用的本地浏览器；
- 逐个询问五把密钥（Serper、SerpApi、DeepSeek、TinyFish、Jev），存到 `~/.marketops/keys.env`，只有本人可读。

然后在 Claude Code 里：

```
/plugin marketplace add ProfessorZhi/marketops
/plugin install marketops-research-assistant@marketops
```

## 用

直接说任务，或者用 `/marketops-research-assistant:research 瑞士户外天然草足球场，找场地负责人`。

插件 = MCP 工具 + skill。主 agent 照 `marketops-research` skill 带一支 agent 团队干活：用宿主自己的多智能体模式（Claude Code 子代理、Codex agent、WorkBuddy 多智能体）开来源、建池、官网、挖掘、整理五组 worker，五段同时推进；脚本是团队手里的批量工具（读页、抽取、搜索、定级）。Codex 和 WorkBuddy 的接法见 [HOSTS.md](HOSTS.md)。

| 工具 | 做什么 |
|---|---|
| `project` | 建立或打开项目文件夹，保存简报，查看进度、成本和余额 |
| `search` | Serper、SerpApi、DeepSeek、TinyFish 四路同时搜，按网址合并；`maps=True` 查地图地点 |
| `pool` | 从下载的开放数据文件建场地池和机构池：过滤、改列名、按运营方归并成机构 |
| `fetch` | Crawl4AI、TinyFish、DeepSeek 三路同时读同一页，每份都保存，联系人取并集；数据文件直接下载 |
| `browse` | 后台用 TinyFish Agent 处理需要点击才能看到内容的难站 |
| `judge` | Jev 对任意池子逐行回答一个选择题，例如是否在范围内、是不是官网 |
| `grade` | Jev 按简报评 A/B/C/D/X，不分语言；agent 也可以手工改 |
| `run` | 后台流水线：每家机构 抓官网 → 评级 → 没有 A/B 就换方法深挖（本地关键词、站内与 PDF、名录、地图、宽搜）→ 补证据；可分片多进程、边建池边跑、续跑、脱离会话运行 |
| `tasks` | 共享任务队列：主 agent 把缺口机构、待复核、难站、数据源切成任务包，多个 worker 并行认领、完成、交回；agent 拿着的机构流水线不碰；`verdict` 记每家的结论 |
| `orgs` | 每家机构一份摘要（扫到了什么、待复核、找法手册、结论），按阶段筛选；`set` 改官网、分类、范围 |
| `export` | 导出 Excel（指标口径写明、分批、待复核标记）和 Bruce 的 18 列路线 CSV |

项目文件夹就是普通文件（`~/MarketOps/<项目>/`）：`brief.json`、`venues.csv`、`orgs.csv`、
`contacts/`、`crawl.csv`、`trace.jsonl`、`costs.jsonl`；网页原件在共享资料库 `~/.marketops/library`。agent 和人都可以直接打开、修改，断了接着跑。

## 0.7.1 更新：agent 做调研，工具可选，阶梯降级，会自我改进

- **agent 做调研**：主 agent 把机构按约 10 家一包分给调研 worker；每个 worker 从头做到尾：用工具一次读完这一包（`run(orgs=…, rounds=0)`，只读页、抽取、定级，不深挖），看摘要，自己深挖，逐家写结论。没有自己跑的后台进程；吞吐取决于开了几个调研 worker。原来的自动管线降为可选的"快速模式"。
- **每个工具都可选，按级降级**：`project()` 报告当前级别（full / reduced / minimal）、缺了什么、影响什么。
  - 没装 Crawl4AI 服务也能启动，读页由 TinyFish、DeepSeek，最后由纯 HTTP 兜底；
  - 没有搜索 key 时，提示 agent 改用宿主自带的网页搜索；
  - 没有 Jev 时，规则先判，其余由 agent 判。
- **多槽位 key**：五家供应商都能配多把 key（`NAME`、`NAME_2`…`_9`，或用逗号分隔）。欠费、额度用完、key 无效或到了红线，就自动切到下一把，用完的那把 6 小时后再试。key 文件（`keys.env`、`MARKETOPS_KEYS_FILE`）改了就生效，不用重启。
- **Jev 真正降本**：规则先判掉明显的行（本机构通用信箱判 D，明显不是这家的地址判 X），Jev 只判真正需要判断的。Jev 不可用时不再让每家机构白等。
- **搜索主力**：Serper 和 SerpApi（地位相同，额度用完时互相替代）加 DeepSeek，TinyFish 同时参与。
- **站点健康分**：死链和死站暂时搁置，会复活。一次失败不算数，要跨时间重复失败或两个读页器都失败才算；我们自己的网络或代理问题不计分；404 只记那一页；反爬只记那个读页器。
- **自我改进**：
  - 工作日志：agent 记卡点、顺畅处、决定和想法，插件也会自动记；
  - 导出时生成脱敏的 RETRO.md；
  - 跨项目知识库：找法手册按市场和机构类型沉淀，失效的自动降权；深挖搜索方法按效果排序。
- **修正**：
  - 门户上的通用页面不再算给几十家机构；
  - 列着多家机构的页面按名字算给对应的每一家；
  - `orgs(add=…)` 可以直接把找到的真正运营方加进池子；
  - 给 agent 的回复更精简（找法手册每次只附一份，去掉重复的链接列表）。
- **模拟**（agent 做调研，60 家，含脚本够不到的路线）：3 个调研 agent 并行，68/68 条路线，零误报，60 家每家都有结论。

## 0.7.0 更新：agent 团队分段协同

- 推动工作流的 skill 重写：主 agent 用宿主的多智能体模式开五组 worker（来源、建池、官网、挖掘、整理），五段同时推进，按 `project()` 的 `stages` 积压调人；脚本扫描是团队的第一遍，不是终点。各组职责在 `references/roles/`，三种宿主通用。
- 新工具 `orgs`：每家机构的摘要（agent 不用重读网页就能决定下一步），按阶段筛选，`set` 改官网、分类、范围。
- `run(orgs=[...], again=True)`：给 agent 用的批量扫描，后台跑，和主流水线并行。
- 找法手册（`project(name, playbook=...)`）：agent 总结某类机构的联系人在哪类页面、用什么搜索词、找什么岗位；脚本对这类机构先读这些页、先跑这些搜索。agent 研究一小批，脚本放大到整类。
- 并行安全：provider 限速全机共享（多个 agent 一起调也不会挤爆 429）；agent 领着的机构流水线先跳过；深挖任务只派流水线做完的机构。
- 页数按收益：页面还在出新地址就继续读（最多 40 页），名录翻页跟到底；连续两页没新东西才停。
- agent 结论（`tasks(action="verdict")`）和交付抽检（工作簿「抽检」页 100 条，`grade(set=[{..., checked}])` 记结果，说明页给准确率）。
- Codex、WorkBuddy 接入说明（HOSTS.md），安装器打印 Codex 配置片段；这两家要在真机上验证。
- 列着多家机构的页面（辖区、联合会、市镇联合体的页面）不再只算给第一家：同一页为另一家读时直接用存档重新解析，不发新请求，地址也算给这一家。
- agent 模拟（60 家，假网络里有脚本模板够不到的路线：场地归市镇联合体 SIVOM 管、负责人在联合体网站）：只靠脚本 51/68 条路线、SIVOM 0/17；3 个挖掘 agent 并行接手后 68/68、零误报；只把 agent 总结的找法写进找法手册、由脚本重扫，不让 agent 挖，64/68，另有 3 条按规则进待复核交给 agent。

## 0.6.6 更新：巴黎真跑（953 家）暴露的问题

- 分片不再互相抢临时文件（0.6.5 四个分片全崩过、靠守护进程重启）；分片只数自己完成的机构；进度里的花费标明是整个项目的，不要跨分片相加。
- 共用门户（paris.fr）：只有本机构自己那一页及其下层算"本站"，别的场馆页面不算；门户域名的邮箱不证明归属。以前每个 paris.fr 页面都算每个场馆的本站，于是跳过了点名检查。
- 共用地址：同一门户上的场馆分开计数（以前合成一家，446 条确认 A/B 实际挂在别的场馆下却没进待复核）；引文旁没点本机构的名 → 待复核；引文旁点了名、一个辖区办公室管 5 家以内 → 照常确认。
- 点名检查要求机构名里最少见的那个词出现（"Paris Saint Germain" 不等于 "HealthCity Paris Saint Germain"）。
- A 必须有人名：找人名后仍没有名字的 A 改为 B。
- 说明页写清口径：广度只算确认的 A/B；对账拆成 确认A / 确认B / 只有待复核的A或B / C / D / 未找到，确认A+确认B 等于广度里的机构数；机构的首选联系人优先取确认的 A/B。
- 编号决策清单：待复核按原因分类计数（低置信度 / 地址挂在别的机构下 / 他站页面）；搜索账户余额为负或到红线时直接列出（以前只有跑的进程知道，巴黎那轮 Serper 余额 -28 没被报出来，全程只能靠更慢的 DeepSeek 搜索）。
- 读页失败在成本账里记下原因（无文本、HTTP 403、超时……），下一轮能区分是页面问题还是供应商问题。
- 模拟（多路线 + 招聘站陷阱）：巴黎、法国、混合三道题与 0.6.5 速度、路线完全相同，零误报。

## 0.6.5 更新：地址归属不再漂移

- 评级按机构算：Jev 的问题里写着机构名和"页面是否在它自己的站上"，以前同一地址加同一段引文的评级会套用到别的机构，谁先评谁说了算（巴黎实测里同一批地址在两版之间换了机构，且不进待复核）。现在每家机构各评一次。
- 同一地址挂在两家机构下、引文旁两家都没点名：进待复核，由人判断归属；不丢，照常交付并标注。
- 模拟（巴黎 80 家，每家多条路线、含招聘站陷阱）：0.6.3 每分钟 31.9 家、路线 21/36；0.6.4 与 0.6.5 都是每分钟 41.0 家、路线 36/36、零误报；Jev 调用数不增。

## 0.6.4 更新：先去掉白干的活和误拦，再提并发

依据：巴黎题实测（0.6.2）加两道题的离线模拟（假网络，读页、搜索、Jev 都有真实延迟）。

**提速**
- 读页"先到先用"：几家读取器同时读，最快的一家读到内容后最多再等 3 秒就往下走；慢的在后台读完，联系人照样补进来。搜索同理（慢引擎的结果进资料库）。每家读取器、每个搜索引擎各用自己的线程池，一家堵住不拖累别家。
- 找人名只查刚评出的 A/B 行，同一地址加同一段引文只问一次，多批并行（之前每轮把所有没名字的 A/B 重问一遍，规模越大越慢）。
- 同一地址加同一段引文只评一次，评过的直接复用；简报 `address_rules`（如 `{"info": "X"}`）在入库时就定级。
- 共用门户（一个域名挂 3 家以上机构）只读本机构那一页及其子页，不再整站爬。
- 各来源轮流进流水线；单进程默认同时 24 家（模拟里 12 → 24 吞吐翻倍，结果不变）。

**不再误拦**
- 只有纯通用信箱（info、contact、office……）直接判 D；secretariat、sports、service、mairie 这类岗位信箱交给 Jev，可以是 B 或 C。
- 他站页面（联合会、名录）上的 A/B，只要引文旁写着本机构名字，就计入头条，只是证据分低一些；不写名字的才标待复核。
- 共用地址挂 3 家以上机构才标待复核（一个市政体育处管两三块场地是常态）。
- 没有官网的机构先按名字和城市找一次官网（域名带名字，或首页标题是它的名字）。

**留痕**：每家机构在 `trace.jsonl` 记一行（各阶段秒数、联系人和 A/B 在哪一步出现）；工作簿"过程（耗时）"页按来源、阶段汇总。

**模拟结果**（法国场景 120 家，与本版第一个提交对比）：同样 12 路并发，每分钟 30.7 → 36.9 家，找到的 A/B 机构 47 → 62（共 62 家，零误报），其中俱乐部 5 → 20；默认改 24 路后约每分钟 77 家（240 家规模，127 家全部找到）。巴黎场景同样全部找到。消融：关掉深挖快一倍，但俱乐部的 A/B 少一半以上，保留。

**业务知识**（来自 Bruce 会话分析 `marketops-session`，每个数字有出处，删掉了没有出处的产出率表）：
- 五个 skill：`marketops-research`（流程，含 Bruce 踩过的坑）、`marketops-brief`（客户/竞品、评级、各国岗位词、交付规则）、`marketops-sources`（建池通道顺序、页面类型产出、来源止损规则、各国起点）、`marketops-tools`（各家搜索/读页/Jev/Agent 怎么用、Bruce 最常用的查询写法）、`marketops-benchmarks`（两道常设题、投入按轮次和人工消息计）。
- `references/projects/`：每条业务线一个文件（法国天然草、英国球场与学校、美国运动场、德国、瑞士、全球高尔夫、其他线），统一模板；新项目结束后用 `/marketops-research-assistant:learn <项目>` 把来源产出、有效页面、岗位词、纠正和基准追加进去，以后的项目自动从这里起步。
- 由此改的代码：人员页（staff/team/board/bureau/Vorstand）优先于联系页、首页（Bruce 实测每百页 A/B 1.73 : 0.18 : 0.08）；跟进俱乐部托管平台上的页面；429/5xx/断连自动重试一次（失败一次不等于死站）；来源跑满 30 家后按 A/B 产出分配名额（≥10% 加倍，<5% 排最后，不丢）。

**按各家官方文档和社区用法调用**：简报的 `country`/`language` 传给 Serper/SerpApi（gl/hl）、TinyFish（location/language）、DeepSeek；TinyFish 搜索按其 30 次/分钟限速自适应，429 时按返回的限额调整；Jev 按 TypeSafe 写法一行一问、选项用可读名字，所选项的概率作为复核信号；每家一份 `skills/marketops-tools/references/*.md`；`evals/` 4 个用例供 `claude plugin eval`。

**Bruce 的需求、卡点和纠正**（`docs/benchmarks/bruce-knowledge/`，他本人 41 天、168 个会话的逐条出处）：他的时间不是耗在抓取上，而是"等"和"重做"。他要的四样东西，本版都接上了：
- 不停的流水线：分片进程死了由守护进程自动拉起（最多 5 次），夜里也不等人；域名解析不了的官网先剔掉，再按名字找现行官网；每个站最多 150 秒，慢站不占工位。
- 从磁盘说真话：进度按落盘的 A/B 机构数、A/B 路线数和 `ab_routes_per_30_min`（他的 ROI 口径：每 30 分钟产出多少）。
- 能对账：说明页"对账"一行，每家机构按最佳等级只计一次，各项相加等于机构数；机构页每行带国家、地区、场景，国家未识别单独计数。
- 一张编号决策清单：`project()` 返回 `needs_you`，所有要用户拍板的事编好号，一次问完。
- 每家机构按 `routes_per_org`（默认 3，他的口径 3–5、最低 1、小机构 1 个就交）挖 A/B 路线；职位按"实际管草坪/场地/设备/外包的人"排，不按职位高低；结果叫"研究有效邮箱"，不叫"可发"。
- 代价实测（模拟，法国 120 家，12 路）：`routes_per_org=3` 比 `=1` 多一轮找第二条路线，每分钟 26.3 → 19.5 家，A/B 机构仍是 73/73、零误报（模拟里每家只放了一条 A/B，所以多出的那轮在模拟里必然空手）；只要一条就交的项目设 `routes_per_org: 1`。三道题（巴黎 80、法国 120、混合 240）全部找到，零误报；与上一个提交相比无退化。
- skill 补上了他实测过的来源（法国公共服务名录 API、NAF 93.12Z、BOAMP/DECP；德国 NRW 与 TED；英国 Pitchfinder、GIAS、Contracts Finder；荷兰 DUO/TenderNed；美国 NCES/IPEDS/ParkServe/CISA；澳洲 ABN；意大利 RES；波兰 RSPO；高尔夫协会名录）、页面类型产出、更多止损线；`references/bruce-prompts.md`（开场、任务书、验收、停线模板对应到简报和报告）、`references/outreach.md`（发信侧规则，只记录交付行要带什么，本插件不发信）。

更早版本（0.6.0–0.6.3）见 git 历史和 Release 说明。

## 规则只有这些

- 邮箱必须原样出现在网页上，不许猜；每行都带来源页面和原文引用。
- 只做调研，不发信。
- 结果先放宽：域外邮箱、X 级都保留并打上标签，以后可以再收窄。
- 每次调用都记账；每个付费账户以首次读到余额的 10% 为红线，低于红线就跳过这家，其他照常跑。没有别的上限。

业务经验见 `skills/` 和 [`references/projects/`](references/projects/README.md)。
