# MarketOps Research Assistant 0.6.4

调研插件：从公开数据集到场地池、机构池，再到带证据、已评级的联系人，最后交付一张 Excel。
给 Claude Code 用。插件只提供能力，流程由 agent 自己掌握。

## 装

```bash
./install.sh            # Linux / macOS。Windows 用 Install.ps1
```

安装器做三件事：
- 建私有 Python 环境 `~/.marketops/venv`；
- 装 Crawl4AI 用的本地浏览器；
- 逐个询问五把密钥（Serper、SerpApi、DeepSeek、TinyFish、Jev），存到 `~/.marketops/keys.env`，只有本人可读。

然后在 Claude Code 里：

```
/plugin marketplace add ProfessorZhi/marketops
/plugin install marketops-research-assistant@marketops
```

## 用

直接说任务，或者用 `/marketops-research-assistant:research 瑞士户外天然草足球场，找场地负责人`。

| 工具 | 做什么 |
|---|---|
| `project` | 建立或打开项目文件夹，保存简报，查看进度、成本和余额 |
| `search` | Serper、SerpApi、DeepSeek、TinyFish 四路同时搜，按网址合并；`maps=True` 查地图地点 |
| `pool` | 从下载的开放数据文件建场地池和机构池：过滤、改列名、按运营方归并成机构 |
| `fetch` | Crawl4AI、TinyFish、DeepSeek 三路同时读同一页，每份都保存，联系人取并集；数据文件直接下载 |
| `browse` | 后台用 TinyFish Agent 处理需要点击才能看到内容的难站 |
| `judge` | Jev 对任意池子逐行回答一个选择题，例如是否在范围内、是不是官网 |
| `grade` | Jev 按简报评 A/B/C/D/X，不分语言；agent 也可以手工改 |
| `run` | 后台流水线：每家机构 抓官网 → 评级 → 没有 A/B 就换方法深挖（本地关键词、站内与 PDF、名录、地图、宽搜）→ 补证据；可分片多进程、边建池边跑、续跑、脱离会话运行 |
| `tasks` | 共享任务队列：主 agent 把缺口机构、待复核、难站、数据源切成任务包，多个子 agent（`marketops-worker`）并行认领、完成、交回 |
| `export` | 导出 Excel（指标口径写明、分批、待复核标记）和 Bruce 的 18 列路线 CSV |

项目文件夹就是普通文件（`~/MarketOps/<项目>/`）：`brief.json`、`venues.csv`、`orgs.csv`、
`contacts.csv`、`crawl.csv`、`pages/`、`costs.jsonl`。agent 和人都可以直接打开、修改，断了接着跑。

## 0.6.4 更新：先去掉白干的活，并行才有用

巴黎题（0.6.2）的实测问题：
- 一半机构的"官网"是市政府门户上的一页。插件把整个门户当成这家机构的官网往下爬，读回来的全是市政公共邮箱。
- 联系人里 75% 是 X，每条都要交给 Jev 评一次。
- 俱乐部后进池，排在 700 多家登记机构后面，跑了近一个小时还没轮到。

本版的改动：
- **共用门户不再整站爬。** 一个网站域名挂在 3 家以上机构名下时，视为共用门户：每家机构只读自己那一页和它下面的子页面。
- **同一地址、同一段引文只评一次。** 结果复用到所有挂着它的机构，以前评过的也直接复用，不再调 Jev。
- **按邮箱前缀直接定级。** 在简报里写 `address_rules`，例如 `{"info": "X", "admin": "X", "book": "X"}`：这些前缀的地址直接按规则定级，不调 Jev；交付表里标为 `graded_by=rule`，可以复核。
- **各来源轮流开工。** 每个来源（登记表、俱乐部名录、学校……）轮流放机构进流水线，后进池的来源不必排到最后。
- **工作过程留痕。** 每家机构在 `trace.jsonl` 里记一行：每个阶段（读官网、等评级、挖掘、证据）花了多少秒、联系人和 A/B 是在哪个阶段出现的。工作簿新增"过程（耗时）"表，按来源和阶段汇总，可以直接看出时间花在哪里、哪个阶段有产出。

## 0.6.3 更新

- 流水线前段也并行：`run` 里多了一条"发现线"，按简报 `focus.find`（找什么）× `focus.areas`（在哪）不断找新机构（地图结果，地图不可用时用网页结果；名录页只取正文里的外链），合并进机构池，流水线立刻接着找联系人。Jev 把明显不在范围的标 `scope=out`，保留但不处理。
- 数据源池 `sources.csv`：每个来源（文件、地图、名录页）一行，记带来多少、新增多少、合并多少；导出"数据源"页算每个来源的 A+B 产出。
- 消融：导出"贡献（消融）"页，按环节（官网/深挖各轮/补证据/Agent）和读取器算独有贡献；`brief.ablate` 可关掉 dig / evidence / reverify / rank / discover 做对照（走资料库，几乎不花钱）。
- 规模：联系人按机构分文件存（`contacts/`），读页只写这一家，几万条联系人也不再串行；`contacts.csv` 是定期快照。
- 修：后台流水线里 TinyFish Agent 结果现在会收回；没有 Jev 密钥时不再每家等 4 分钟。
- 精简：删掉被 `run` 取代的 `crawl` 工具（工具 10 个）；技能重写成"五个池子同时填"的一页。

- 池子是所有来源的并集：`pool` 对每个来源调用一次（开放数据、各联合会俱乐部名单、地图结果、协会名录、自己整理的名单），同一场馆（名称 + 邮编/城市）或同一机构（官网，否则名称 + 城市；一方缺城市时同名唯一即合并）跨来源合成一行，空字段互相补齐，`sources` 列出全部来源；名字差太多的交给 `judge` 判断是否同一家。

## 0.6.2 更新

- 持久化共享资料库 `~/.marketops/library`（可用 `MARKETOPS_LIBRARY` 指到团队共享盘）：网页原件和搜索结果所有项目共用、跨插件版本保留；30 天内读过的页面、14 天内搜过的查询直接复用。每条联系人记首次发现和最后核实时间；超过 30 天的 A/B 会回原页核实，不在了标"页面上已找不到"，不删。
- 交付：机构表一家一行，带首选联系人（姓名、岗位、邮箱、证据、来源页）、机构电话、名下场地、未找到原因；联系人表加"名下场地""最后核实""首次发现"。
- 提速：一家机构的页面 4 页同时读；慢读取器超时 40 秒；补证据每家最多 3 条且并行。6 家俱乐部从零开始 153 秒（之前约 7 分钟），资料库已有时 66 秒。

- 流水线：每家机构单独流过 抓官网 → 评级（后台评级器批量）→ 没有 A/B 就深挖 → 补证据 → 完成，几十家同时在不同环节；`run(follow=True)` 让建池 agent 边加机构边处理，`run(pool_done=True)` 收尾；长跑每半小时刷新一次工作簿。
- 证据打分：每条联系人 0–100 分（强/中/弱），写明依据；证据弱的照样交付并标"证据少"，由人决定；流水线用邮箱本身搜索补证据，工作 agent 可领"补证据"任务包。

- 多 agent 并行：`tasks` 队列加子 agent `marketops-worker`；`run(shards=N)` 把机构池切给 N 个进程并行跑；项目文件带跨进程锁，多个进程和 agent 同时写也不会写坏。
- 供应商权重：`brief.providers` 设各家参与比例（默认：DeepSeek、TinyFish 搜索与读页、Crawl4AI、Jev 放开用；Serper 0.5、SerpApi 0.3；付费的 TinyFish Agent 只在明确开启时用，每轮最多 20 页）；抽到的几家结果单薄时自动补上其余几家，不漏信息。Crawl4AI 始终参与。
- Jev 给深挖线索排优先级（只排序不删）；评级 8 路并行；单进程默认同时 12 家机构，本地浏览器最多 10 个标签页。

- 广度优先：头条改为"有 A+B 的机构占比"，另报每机构最多计 3 条的路线数；同一人两个地址计一条。
- 待复核写明原因；同一网站下多个账户共用的地址不再算"共用"；评级口径排除赞助人/支持者俱乐部、节庆酒吧、单队教练。
- A/B 行由 Jev 从引文片段里挑出姓名和岗位，交付不再空着。
- 电话尾数粘进邮箱的情况以 mailto 为准修正；电话单独存 `phones.csv`。
- `run` 作为独立进程运行，会话结束也继续；`run(stop=True)` 优雅停止并导出；进度写明每分钟机构数、剩余时间、每机构成本；目标改为机构占比，深挖轮次照常执行。
- 新工具 `pool`：从开放数据文件直接建池（过滤、映射、按运营方归并）。
- 抓取时新闻、活动、博客类链接降权，大门户不再把页数花在新闻上。

## 0.6.1 更新

- 抓取：默认 15 页、按链接打分往下两层，站内 PDF 交给 TinyFish/DeepSeek 读；同一网址一个项目只抓一次。
- 引文按页面结构取（只含这一个邮箱的卡片或行），卡片布局不再错位。
- 评级：告诉 Jev 地址自带的岗位词、该地址还挂在几家机构、页面是否在本机构网站；低置信度、共用地址、他站页面的 A/B 标"待复核"，不计入头条指标。
- 长程：`run` 一轮轮深挖直到达标或连续两轮无新增；`python scripts/server.py run <项目>` 可无人值守。
- 指标改名并写明定义；新增分批表与 18 列路线 CSV；作业按项目隔离；通用信箱规则判 D 后不再被改。

## 规则只有这些

- 邮箱必须原样出现在网页上，不许猜；每行都带来源页面和原文引用。
- 只做调研，不发信。
- 结果先放宽：域外邮箱、X 级都保留并打上标签，以后可以再收窄。
- 每次调用都记账；每个付费账户以首次读到余额的 10% 为红线，低于红线就跳过这家，其他照常跑。没有别的上限。
