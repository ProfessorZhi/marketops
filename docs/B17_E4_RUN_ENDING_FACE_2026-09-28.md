## 一、这一片关掉的两句话

**第一句（e4-1）**：主张那一侧原来收的是 `promote_receipt` 的 `PromotionOutcome`
序列。那条路在**受理解析面**上是写不出来的 —— MCP 那一层要交出 `close_run` 的
`folded`，就得现造一个 `PromotionOutcome`，而 `asset` 要么是真 `VenueAsset`、要么是
空，其余几格（`disposition` / `account` / `evidence`）会变成**伪造的报告字段**。
一个造不出来的参数就是一扇没装的门。

**第二句（e4-2）**：即使主张收窄了，服务面上仍然没有「结束一轮」的入口。收口矩阵
（`docs/B17_ACCEPTANCE_MATRIX_2026-09-28.md`）的条件 2 那一行当时逐字写着「消费者：
**零**」「`close_run` / `stop_run` / `end_run` 一条都不存在」「盘上没有任何生产路径能把
一个 Run 结束掉」。⇒ **一个 Run 的产出，没有任何一处会写下来。**

两句是同一件事的两半：前一句是「那条路走不通」，后一句是「那条路根本还没开」。

## 二、主张收窄成句柄（e4-1）

`close_run` 与 `reconcile_run_delta` 的 `folded` 从 `PromotionOutcome` 序列改成
**一串池子句柄**（`application/pool.py::venue_handle_for_row` 那种字符串）。

`fold_claim(handles) -> tuple[str, ...]` 是主张**唯一**的规范化点（升序、去重），进
`__all__`。**两侧用的是同一份实现，不是各写一遍** —— 写两遍的话，一次比较会在某一个
读法上不等、在另一个读法上相等，而两处报的都是「不一致」。`claimed_folds` 随之删掉：
全仓除自身 `__all__` 外零消费者，而它的判据已被账本取代（§503：「只有类名/字段/接口的
无消费者实现不算完成」）。

**「回执里哪些行真的落了盘」这一格的判据因此换了主体**：e4 之前是**过滤器**
（`PromotionOutcome.asset is not None`），之后是**账本**（`RunStore.folds_of`）。账本强
于过滤器 —— 过滤器只知道 `asset` 那一格是不是空的，账本知道那一行**在不在**，而它与
池子那一行同生共死（同一个写事务）。`''` 与 `()` 仍然是**真的读数**（「这一轮一行都没
折」），不是缺席。

## 三、结束面（e4-2）落地的三处

缺一处这一片就是「类名/字段/接口有了，而服务面没有」。

1. **`get_run` 多一格 `folds`** —— 账的**读面**。`folds_of` 的三种结局不许在这一层
   塌成两种：读不出来时**必须抛**，且要接住换成 `ToolError`（不接的话 SDK 会把它换成
   一句通用的 `UnexpectedToolError`：一次「账读不出来」会读起来像一次内部崩溃，而它
   其实是一条准确的、点名了这一轮的判定）。**绝不报一份空表** —— 报空表就是那条假账
   本身：折了却没记，回执上写着「一行都没折」，而池子已经变大了。
   **次序是读数，不是排序**：账记的是那次写发生的先后；把它排成升序会让「池子那一行
   是这一步写下去的」这件事丢掉。它与 `fold_claim` 那一侧的升序**不是同一件事** ——
   那边是主张的规范化，而主张没有先后可言。
2. **`close_run(run_id, delta, status, folded=None)`** —— 交一份完整 Delta 与一个结局，
   账平了才停表。它**不自己核对账**：两道闸都在
   `application/run_reconciliation.py::close_run`，工具只做两件事 —— 把调用方的载荷翻成
   域对象、把四类拒绝（账读不出来 / 账对不上 / `ending_refusal` / 已经结束过）原样交
   出去。`_one_run` 那一句守卫排在应用层之前：未知 id 与跨工作区与「账对不上」处置相反，
   不能混成一句话。
3. **`run_handlers` 多要第五样 `assets`（`VenueAssetStore`）**，组合根传**同一个池子
   闭包**。它**不加 `| None`**：缺省会把「忘接池子」推迟到结束面，而那时这一轮已经在
   跑了。

三处助手各有一处能红的地方：`_status` 是**闭集**且报出集合（一个不在集合里的词此后会被
读成一个新结局，而在报告上它与三个真结局逐字同形）；`_claim` 拒空串（它会进
`fold_claim` 的集合，变成一个**永远对不上**的句柄 —— 一次正常的结束被报成「主张多报了
一条」，而调用方拿那个回执去改的地方是错的）；`_delta` 收下映射，或给一句指得出字段的
拒绝（一份形状不对的产出会被读成「每一格都空的那一份」）。

### 结束回执**不**报 `folds`

两份各报一次同一串，先漂的是「哪一串才算折进去了」，而两边都声称自己报的是同一件事
—— 于是没有哪一份能被判成错的。所以**结束面只写、`get_run` 只读**。判据是**集合逐字
比**：结束回执的格子 == 读回面那一份**减去** `folds`。只判「结束面里没有 `folds`」是
不够的 —— 那样一个把 `stopped_at` 漏掉的实现照样绿。

## 四、三道闸里有两道在服务面上**够不到**（实测）

`folded` 那一格的出参 schema 是 `list[str] | None`、`delta` 那一格是对象，所以
`[None]` / `[1]` / 裸字符串 / 非映射的 `delta` 在进到函数体**之前**就被框架拒了。实测
拒词：成员级是 `folded.0 / Input should be a valid string`，整格是
`folded / Input should be a valid list`，`delta` 是 `Input should be a valid dictionary`。

这与 `_window` 那一处**同一条**（既有先例：
`tests/test_mcp_runs.py::test_the_windows_own_shape_guard_still_fires`）：按**类型**的闸
是给库调用方的第二道，服务面判据落在框架那两句拒词上 —— 要点名字段，也要说出这一格要
的是什么。所以判据两半各判一次：

* **服务面**判框架的拒词（三条形状逐个钉它自己那句：`[None]` 与 `[1]` 落在成员上、
  裸字符串落在整格上）；
* 助手那道闸**单独直判**（`_parse_claim(shape)` / `_parse_delta(shape)` 各抛
  `ToolError`）。

真正走进 `_claim` 的只有**按值**的那条路：`[""]` 与 `[V1, ""]` 都是合法的 `list[str]`。
这就是「一道闸在服务面上有没有执行器」的实测分界 —— **同一个函数里按值的闸够得到、按
类型的闸够不到**。

## 五、变异控制 12/12，其中两条改的是**判据本身**

口径只有一条：`exit == 1` 且红名单非空。驱动与输出在 artifacts 那一侧
（`TARGET-CONVERGENCE-B17/mutation/e4-2/`），列在这里只记它教了什么：

* **「删掉 `isinstance(declared, str)` 那一支」实测 SURVIVED，而这是对的。** `str` 不是
  `(list, tuple)`，所以否定的那一支照样拒它 —— 两支说的是同一句话。**承重的变异方向是
  放宽**（改成「可迭代就行」）：那时裸字符串会被**逐字符**读成十六个句柄，不抛、不空。
  判据据此改成判这个方向。
* **「结束回执多报一格 `folds`」实测 SURVIVED**：当时**没有任何判据**在判这件事，而代码
  与文档都在承诺它。据此补上
  `test_the_ending_receipt_does_not_re_report_the_folds`，它随即 KILLED。

**这两条值得留下来**，因为它们是同一类事故的两个方向：一条是一个**看起来像闸、其实是
同一句话**的分支（判据该改），另一条是一句**没人执行**的承诺（判据该补）。剩下的十条
各自钉住一处承重实现：`get_run` 把账本错误吞成空表、不把主张交给对账闸、两个形状闸、
未知结局取缺省、不接住 `RunFoldLedgerError`、丢掉 `_one_run` 守卫、不报 `folds`、把
折入次序排成升序。

## 七、这一片**不**做什么

* **不给「谁有权宣布一轮做完了」加判据**：`status` 由**做事的这一方**给，服务端没有这份
  答案可以替它说话。这一格放进允许表是**承认一处缺口**，缺口的另一半归 B01/B02。
* **不把 `close_run` 做成「结束」的第二个入口**：`RunStore.stop` 照旧是唯一的写路径，
  这一片只是给它加了两道前置判据。
* **不动 `RunDelta` 的形状**，不给它加字段；也不给 `usage` 造一个生产者（那是条件 4
  那一行的事）。
* **不改 `_window` 已经立下的那条口径**：够不到的闸照样留着给库调用方，服务面判据判
  框架的拒词。
