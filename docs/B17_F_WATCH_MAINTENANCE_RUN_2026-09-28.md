## 二、条件 5 两半各自的处置

### 前半句：关在「创建」这个动词上，而它**不**声称后半段

「watch 只为到期/信号对象创建维护 Run」—— 判据 1 与判据 2 合起来正好是这一句：
**有**到期/信号就创建、**没有**就不创建。

「创建」这个动词落在**受理一行 Run** 上，口径与条件 4 那句「不创建下一 Run」相同
（那一片也是拿盘上的行数当「创建」的证据）。

**它不声称的是**：「这条 Run 跑起来真的去维护那些到期格子」今天**不在射程内**。全仓
没有任何执行器把一行 `Run` 变成工作中 —— Run 内部跑 Job / WorkItem / Quay attempt，
那一层是 PR #8 的既有实现，而**把它接到 `Run` 上不是这一片**。条件 5 逐字说的是
「创建维护 Run」，这一片判的正是这一个动词；把「跑起来」也读进来，就是拿一句没测过的
话当结论。

### 后半句：主语不在，**换主语**

`SavedView` 在 `marketops/` 与 `tests/` 下**零命中**（全部命中都在 `docs/`；收窄矩阵
逐字把 `SavedView` / `Watch` / `ActionItem` 三个对象划给 **B24**，并逐字写着「本行只
登记归属，不在 B17 里造它们」）。同族的 `ActionItem` 也不存在，而 `RunDelta` 那一侧
自己记着这件事（`marketops/domain/run_delta.py:69` 逐字：「`ActionItem` 在本仓**不存在**」）。

⇒ 处置与 e5 同款（那一片把「第一轮」换成「账」）：**判这一层实际在做的那件事，而它
是判得动的** ——

判据 4 取的是**两个最像会越界的读者**：`get_run_increment`（它读整本维护账，现算一份

## 三、机制：改了三处，各自为什么

### (1) `marketops/ports/runs.py:177` —— 删掉 `watch` 那一段

被删的那一段说的是「它的来源（到期/信号/日程）**还没有生产者**」。那句话在切片 f
之前**是真的**，f 之后**不再成立** —— 删掉的是一句当时为真、现在为假的话，不是一个
检查。

它**不能**搬进 `admission_refusal`，理由是这个函数自己的 docstring 逐字写着的那件事：
它是**纯函数**（只读 `spec` 与 `at`），而「这一批主体上今天有没有到期」**随盘上的行变**
（观测与信号是维护账上的行）。这与 e2 把旧的那一句话拆成两句的理由同款 —— 拆开的理由
不是把一句话分成两句好看，是**那两句要的输入不同**。

### (2) `marketops/application/run_admission.py:228` —— 新增 `_require_due`

它是「**读盘在外、判定在内**」的**第二次**应用（第一次是 `:311` 的 `_spent_of`，
`ports/runs.py` 那一节逐字说过这件事）。三个分支各自说清缺的是哪一样：

* **两个存储没递进来** ⇒ 判不了。判不了既**不能**读成「没有到期」（那会把一个没有任何
  依据的 watch Run 受理下来），也**不能**读成「有到期」——只能拒。
* **场景今天不派发** ⇒ `due_work`（`application/maintenance.py:386`）自己会说，原文
  照旧、只把类型从 `ConfigError` 换成 `RunSpecError`：`ConfigError` 说的是「部署/配置
  写错了」，而「这个场景今天暂停」是一个**正常状态**。
* **一条都没有** ⇒ 这一条要的正面事实不存在。

调 `due_work` 而**不是**直接调 `what_is_due`（`domain/maintenance.py:612`）：前者多做
两样这一条同样要的事 ——「场景今天派不派发新工作」与「账从哪读」（它读
`record.workspace`，而不是让这一层自己拼一个工作区）。这是「两个来源，一处派发」那句
话的落点。

调用位置在 `_spec_of` **之后**、`store.admit` **之前**（`:200`），两条理由各不相同：
域层那条跨格校验器必须先说话（它判的是「这两格说的是不是一件事」，比「今天有没有到期」
更根本）；而这一步必须在写之前，因为它要**写下的行数是零**。

### (3) `marketops/adapters/mcp_server/runs.py:174` —— `submit_run` 收下主体来源

`name` / `cohort` 两个参数经 `_subject_source`（`product_loop.py:3332`）→
`_subjects`（`product_loop.py:3438`）派发。复用而不新写第二处派发：`what_is_due` 的

**只在 `watch` 上展开**（`:323`），与窗口那两行同一条纪律。反过来那一支（`:336`）
**拒，不忽略**：`name` / `cohort` 在别的模式上一个字都不读，而一次被静默吞掉的参数会让
调用方以为它约束了什么 —— 与 `window` 在 `manual` 上被拒是同一条理由。

组合根（`interfaces/mcp/__main__.py:701`）把两个**已经在场**的工厂多传一个消费者

的调用点之前。**没有新的接线基础设施。**
