# 法国巴黎室内运动场馆 · 全量（0.6.2 题）

0.6.1 的巴黎题为了开发提速，只取了 738 家里打分最高的 150 家。这道题**不缩小**：按原始需求把巴黎做完，
并且在上一轮的基础上**续跑**，检验插件“不从头再来”的能力。

## 1. 原始需求（逐字，不变）

```text
@Vince.Huang 麻烦调研一下法国巴黎所有室内体育场馆的名单，然后找到最适合的，高ROI的
触达信联系人的邮箱，确保邮箱具体到岗位和个人，排除info，admin，book这一类工单或者前台邮箱。
```

范围：巴黎市（INSEE 75，20 个区）。

## 2. 池子：不止一张登记表

“所有室内体育场馆”的联系人，远多于场馆登记表里的业主。池子按四类来源建，全部进同一个项目：

| 家族 | 来源（示例） | 进哪个池 |
|---|---|---|
| 场馆业主/运营方 | RES 普查 `dep_code="75" AND equip_nature="Intérieur"`（1,787 条设施 → 738 家机构） | 场地池 + 机构池 |
| 在这些场馆活动的俱乐部与协会 | 各项目联合会的俱乐部查询（篮球、排球、手球、羽毛球、乒乓、击剑、柔道、体操、游泳、攀岩……）、巴黎市协会名录 | 机构池 |
| 学校与大学体育部门 | 大学 SUAPS / 体育服务、高校与中学体育馆运营方 | 机构池 |
| 私营与连锁场馆 | 攀岩馆、室内五人制足球、壁球/羽毛球馆、综合体育中心、连锁健身场馆 | 场地池 + 机构池 |

规则：
- 不许只取前 N 家；
- 每类来源记一行：列出多少家、进池多少家；
- 同一机构只研究一次，名下场馆用 `org_id` 关联。

## 3. 分级契约（沿用 0.6.1 巴黎题，比 Bruce 默认严两档）

| 档 | 判据 |
|---|---|
| A | 具名人员 + 岗位 + 工作邮箱在同一官方记录里绑定，岗位能决定或直接运营场馆 |
| B | 岗位专属信箱（`responsable.gymnase@`、`regie.piscine@`、`direction.sports@` 之类），或能转达的运营/管理岗个人 |
| C | 场馆业务入口：service des sports、location d'installations、secrétariat sportif |
| D | 无岗位绑定的官方通用入口（`mairie@`、`administration@`） |
| X | 出题人要求排除：`info@` / `admin@` / `book@` / `booking@` / 前台 `réservation` / `standard@`；通讯、市场、HR、财务、票务、会员；no-reply；纯室外 / 非体育设施 |

写进简报（`brief.json`）的 `grades`。`focus` 用法语岗位词和名录词，例如：
- `search_terms`：`responsable équipement sportif`、`directeur du gymnase`、`régisseur`、`chef de bassin`、`président club contact`、`bureau du club`
- `directory_terms`：`annuaire clubs Paris <sport>`、`ligue Île-de-France <sport> clubs`、`SUAPS contact`

## 4. 跑法（0.6.2，全部默认参数之外只写下面这些）

1. 在上一轮巴黎项目（0.6.1 的 150 家）基础上**续跑**：同一个持久资料库（`~/.marketops/library`）。不许另建空库，这道题要验证复用。
2. `pool` 从 RES 导出建场地池和机构池，追加到同一个 `orgs.csv`。
3. `run(project, follow=True, shards=4)`：边建池边跑。
4. 同时派 3–6 个 `marketops-worker` 子 agent：
   - 先领建池任务：其余三类来源，每类、每个项目或每几个区一包；
   - 再领 `dig`、`review`、`evidence`、`browse` 任务包。
5. 池子建完：`run(project, pool_done=True)`；流水线跑完后 `export`。

## 5. 指标

| # | 指标 |
|---|---|
| 1 | 广度：有 A+B 的机构占比（总的，以及每类来源各自的） |
| 2 | 每百机构 A+B 路线数（不封顶 / 每机构最多 3 条） |
| 3 | 具名 A/B 联系人数（`contact_name` 非空） |
| 4 | C / D / X / 未找到；**被排除的工单和前台信箱数**（本题核心要求，单列） |
| 5 | 覆盖率（有 A–D 任一路线的机构占比） |
| 6 | 证据强/中/弱的分布；待复核数和原因分布 |
| 7 | 精度：随机抽 60 条 A/B，逐条开原页核对四项（字面存在、同块绑定、岗位在口径内、未被排除） |
| 8 | 成本、总耗时、每分钟处理几家机构、人工插话次数 |
| 9 | **复用**：资料库命中的页面数和搜索数，与上一轮相比省下多少调用 |
