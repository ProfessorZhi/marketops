## 这一轮新发现的卡点（产品侧，不是题目侧）

1. **`run` 只有启动，没有停止。** 三道题并行时想停掉一道已经过期的跑（范围被改小了），
   没有任何动词可用；唯一办法是停掉整个 MCP server，三个跑一起断，再逐个用 CLI
   headless 续起来（`run` 可续，页面缓存与已完成机构都不重做）。一个后台长任务没有
   停止面，等于把“跑错了”变成“只能等它烧完”。
2. **没有“从数据源建池”的步骤。** `run` 的前提是 `orgs.csv` 已经存在；巴黎 738 家、
   全国 50,719 家都是我手写脚本从 RES 普查数据聚出来的，插件里没有 import/discovery。
   题面说“调研所有场馆的名单”，名单这一步在插件之外。
3. **规模与成本没有换算面。** 池子多大、分几波、每波多少、每波几轮，全在插件外面用人工算；
   插件只报“花了多少”，不报“这些钱买到多少机构、还差多少没跑”。
4. **MCP 会话与后台跑绑定。** 停掉 MCP server 之后，本会话的九个工具全部不可用，
   只能改用 `server.py run` 的 headless 路径；后台跑的寿命因此挂在会话进程上。
5. **前一轮记录的九个缺陷本轮仍是待验项**（`contact_name` / `contact_title` 导出全空、
   `review` 无原因列、电话尾数并进邮箱本地部分、主指标按行计不封顶、goal 在第 0 轮达成
   导致深挖轮次不执行、低置信 A/B 未拦、同一人两地址计两条、大机构门户导航失手、
   工作文件被电话灌满）。英国回归与巴黎两题跑完逐条复核。

## 这一轮的新事实（题目侧）

- **英国题的 344 不是“全英国”**：它是 Bruce 全族 5,596 家机构 / 6,292 个账户里的 5 批切片（5.4%）。
  取这 5 批是因为它们同一天、同一流水线跑完，且三个线程回执与主表逐批行数相等（77/88/63/72/76），
  是全族里唯一能逐批复核的连续段。回归要求输入逐字相同，所以这一题既不能缩也不能扩。
- **法国题从“全国”收回到“巴黎市”**：出题人明确这一阶段只看城市级。全国池子（50,719 家机构 /
  87,688 条室内设施 / 108 个省）已经建好留在本机，随时可以按波开跑，但不在本轮判定范围。
- **巴黎题的判据比 Bruce 默认严两档**：`info@` / `admin@` / `book@` / 前台 `réservation`
  从“研究资产”降为 `X`（不算路线）；A 与 B 都要求岗位绑定，不再允许“相关部门信箱”混进 A/B。
