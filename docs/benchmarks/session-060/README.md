## 3. 代号表

| 代号 | 含义 |
|---|---|
| `P01`… | 一个人。同一个真人在全文用同一个代号，所以"这一行的人"和"引文里的人"是不是同一个，看得出 |
| `ORG01`… | 一个机构 |
| `org07.example` | 一个机构的域名；同一个域名的行一眼能对上 |
| `roleword@org07.example` | 角色信箱（`facilities@`、`sbm@`、`bursar@`…）。**角色词保留**，因为这类信箱的评级正是要分析的对象 |
| `p109@org07.example` | 个人信箱，`p109` 指向 `P109` |
| `x@org07.example` | 本地部分无法归类（既不是人名也不是角色词） |
| `«phone»` `«postcode»` `«secret»` `«host»` | 电话、邮编、凭据形状的串、认不出的域名 |

`ORG` 与 `host` 用同一套编号：`ORG07` 的站点就是 `org07.example`。

## 4. 脱敏方法与自检

红线（绝不出库）：第三方姓名（含小写 slug 形态）、邮箱、电话、机构名、域名、邮编、凭据。
做法：

1. **名字与机构的清单来自数据本身**：两个运行目录的 `orgs.csv` / `contacts.csv`、基线的
   `task_input.csv` / `baseline_rows.csv`，再加人工复核。
2. **人工复核的残留清单**：先跑一遍，把文档里所有"两个首字母大写的词"和所有首字母大写单词
   列出来，逐条判断是岗位还是人名。岗位留下，人名与地名/机构名进本地 `blocklist.txt`（**这份清单本身含真名，只留本机，不入库**）。
   这一步重复到残留只剩岗位词与产品词为止（当前 128 条残留，全部是
   `Premises Manager`、`Leiter Sport` 这类）。
3. **形态规则兜底**：`Mr/Mrs/Miss/Dr` + 名字、`名.姓` 形态的 slug、`名-姓` 形态的
   artifact id、只有本地部分的邮箱（`someone@` 后面没有域名）都会被识别。
4. **`verify.py` 是闸门**：邮箱、电话、邮编、凭据、真实 URL、尊称+名字、以及清单里
   每个真名是否仍出现，任何一项非零就退出非零，不许提交。
5. 上一次同类摘录（PR #65）漏过人名的教训已被写进第 2、3 条规则——泄露形态是
   小写 slug（`first-last` 形式的 artifact id）和只写本地部分的邮箱，这一版都覆盖了。

## 5. 已知的取舍

- 截断：工具结果 1500 字符、参数 900、推理 700。想看全文的行为在结果文档与本地数据里。
- 少数既是大写词又是英语常用词（如 `Green`）的残留保留为普通词，不当作姓氏。
- 机构与人都成了代号，所以**只能做相对比较**（"同一页上 A 与 B 是否同一人"），
  不能反查是谁。
- 摘录里包含操作员的判断与自述，它们不是插件输出；每段都标了方向（`→` 调用 / `←` 结果）。
