## 3. 选择理由

1. **唯一同时满足「≥10 会话」与「≥1,000 家可证机构」的候选。** 英国、美国会话更多，
   但转录里能落到账户的只有 12 / 13 家；法国是 1,874 个 `account_id`、249 个带等级账户。
2. **产出天然就是 A/B/C/D 表。** 23 列评估表直接带 `role_priority` 列，取值前缀即档位
   （`A_*` / `B_related_operator` / `C_relevant_official_business_entry` /
   `D_official_general_research_entry`），不需要另设映射规则。
3. **合并去重是这项业务本身的一部分。** 该族内另有一张 16 列去重表，主键 `institution_email_key`，
   带 `source_batches` / `source_row_refs` / `unique_route_count` / `duplicate_source_count`，
   正好对应判据 2 的「合并 + 去重」。
4. **区域与机构类型单一。** 同一国家、同一类机构，业务主题是两个产品在同一场景下的组合，
   不跨行业。
5. **投入量级可用。** 12 个会话、422 条人类往返、740.9 小时跨度，足以构成人工基准，
   又不像美国候选那样 27 个会话跨 5,859 小时、边界无法界定。

代价与风险：

- 法国的表是 **23 列**，不是题面写的 18 列（见 §8）。
- 语料里**没有完整交付 CSV**：能逐户复原的是 249 个账户的**等级**，
  不是全表的邮箱/联系人/证据文本（见 §7.3）。

## 4. 合并去重规则

三级优先级：

1. **主键 `account_id`**（`I` + 9 位数字）。同一 `account_id` 视为同一机构，跨批次、跨会话合并。
2. **回退键：机构域名 + 规范名。** `account_id` 缺失时：
   - 域名取邮箱 `@` 后部分，小写、去尾点、去 `www.`；免费邮箱域不参与机构判定。
   - 规范名小写、去重音符号、去标点、压缩空白，剥离法律后缀与通用后缀
     （sarl / sas / sasu / eurl / sa / sci / association / club / mairie 等）。
   - 二者同时相同才算同一机构；只有域名相同、规范名不同时保留两条并标 `conflict_status`。
3. **邮箱级去重键 `institution_email_key`** = 机构键 + 规范化邮箱。同一机构下多个邮箱保留为多行，
   `unique_route_count` 计数、`duplicate_source_count` 记重复来源。

机构级 A/B/C/D 取该机构所有联系人路线中的**最高等级**（A > B > C > D）。

## 8. 对题面判据的修正建议

1. **判据 3 的「18 列」应放宽。** 法国是 23 列。建议改成「至少含 `account_id`、联系路线类型、
   分级来源三列的路线表」，18 列作为其中一种实现；否则两个候选都会被判不通过。
2. **判据 2 的「合并去重」应写明键。** 按 `account_id` 去重与按域名去重差一个量级，
   不写清会被质疑换表。本题取 `account_id`。
3. **判据 4 的「时长」建议同时报「跨度上界」和「会话数 + 往返数」。** 跨度含跨天空闲，
   单会话最长 167.6 小时显然不是连续工作。
4. **英国候选不建议弃用。** 它是唯一带「发信 Wave 1–4 + 回复监控」完整闭环的候选，
   如果 062 的目标包含触达效果，英国是唯一能提供回复数据的族，适合作为第二基准题。
