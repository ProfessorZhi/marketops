# 聚合 Bruce 的工作 · 一次跑完他分散在多次会话里的调研（0.6.2 题）

Bruce 的调研分散在很多次会话、很多批次里，每次做一小块，质量参差不齐。插件的目标不是复刻某一批，
而是**把他在一个区域里分多次做的事，一次性、连续、自动地做完**，并且在广度、数量、质量、速度、成本上都明显超过他。

## 1. 选题（由东京 CC 从 Bruce 语料里定，写清理由）

条件，全部满足：

1. **同一区域、同一类机构**：Bruce 在这个区域做过很多次（≥ 10 个会话或批次）；
2. **规模 ≥ 1,000 家机构**：把这些批次的输入**合并去重**后的机构数；
3. **Bruce 的产出能逐账户复原**：有他的路线表（18 列 `qualified_email_routes.csv` 或等价表），能算出他的 A/B/C/D；
4. **能算出他的投入**：会话时间戳加起来的总时长、会话数、人工往返次数。

候选：英国运动场/学校这一族（5,596 家机构里，取一个郡、地区或连续多批，凑满 1,000 家以上）、
瑞士足球族的全量，或其他 Bruce 跑过多批的族。按上面四条打分选一个；条件允许时，选两个国家各一个。

写 `docs/benchmarks/bruce-aggregate-062/SELECTION.md`：候选对比表、选择理由、合并去重规则、Bruce 的批次清单（只写批次号和计数，不写机构名）。

## 2. 输入

- 合并去重后的机构表 → `orgs.csv`，列为 `id, name, website, city, batch`。`batch` 保留 Bruce 原批次号，导出时按批次对照。
- 分级契约：照抄 Bruce 当时的 `fjd-email-role-qualification`。岗位词用当地语言写进 `grades`，`focus` 也用当地语言。

## 3. 跑法

- 插件冻结在 **0.6.2**，测试期间不改代码。
- **全新空资料库**：`MARKETOPS_LIBRARY` 指向一个新文件夹，保证速度和成本对比公平（不吃巴黎题或以前跑过的缓存）。
- `run(project, shards=4)`，派 3–6 个 `marketops-worker` 子 agent 领 `dig`、`review`、`evidence`、`browse` 任务包。
- 全程自主；人工插话全部记录。

## 5. 判定

- 广度（有 A+B 的机构占比）≥ Bruce × 1.3；
- 具名 A/B ≥ Bruce × 1.3；
- 精度 ≥ 90%，并且不低于 Bruce 抽检的精度；
- 总时长 ≤ Bruce 总时长的 1/5；
- 人工插话 ≤ 3 次。

“只有 Bruce 有”的账户要逐个分析：插件为什么没拿到？只写通用缺陷，附复现方式。

## 6. 数据边界

Bruce 语料和逐账户明细只放东京本机；进 Git 的文档只写计数、批次号和结论，不含第三方姓名、邮箱、电话。只做调研，不发送任何内容。
