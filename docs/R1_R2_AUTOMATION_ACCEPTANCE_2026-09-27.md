## 3. G1 的八条「必须失败的对照」

计划 §3 逐字列了八条。本仓的处理是**把它们做成一张表**：`CONTROLS`
（`tests/test_r1_vertical_acceptance.py:1118` 起，到 `:1217`），每条带**判据**与**执行器**
（各两条，共十六个），并由 `test_every_control_names_a_real_executor` 核查。

**下表只重述 `name` 与 `criterion`，不重抄执行器** —— 执行器逐字住在上面那个位置，
重抄一遍只会多一次转写出错的机会（本报告初稿就在这里抄错过两条，是核对源码时发现的）。

| # | 对照（`name`） | 判据（`criterion`，逐字） |
|---|---|---|
| 1 | 错国家被标 eligible | 一个国家不在范围内的账号必须被判 irrelevant（规则**真的生效**），而不是因为那一格没被生产出来而落进 unchecked |
| 2 | 目录别人的邮箱被绑定 | 同一页上属于另一家组织的邮箱不得归属到目标账号（归因层），而引用另一账号的证据要整份拒绝（引用层） |
| 3 | 人工 YAML 是必需 | 干净数据根上一个 operator 清单都没有时，发现 → 晋升 → 列账号 → 冻名单 → 起草整条链照跑，且**不生成影子 YAML** |
| 4 | 重复 route 计新增 | 同一次观察重放不产生第二行路线（投影不变、id 相同），重发同一份材料不写第二条变更信号 |
| 5 | 空正文声称镜像成功 | 取回成功而正文为空时，那一趟**不得**被当成一页内容：工具面要说得出它是空的（`unparsed`），且那一趟不落证据行 |
| 6 | X 被包装为关键联系人 | 等级 X 不产正常草稿，而且它给出的理由是**停它的那条规则**，不是一句笼统的「不适用」；只有关键联系人的等级进得了第一触达 |
| 7 | 跨 workspace 证据 | 另一个 workspace 的行走不到（**拒绝**而不是返回空），写进去要拒绝 |
| 8 | 单页坏时间使全批无回执 | 一页的时间戳坏掉时，那一页自己落一条结论（`invalid_source_time`），而**同一批其余各页照常**有回执 —— 坏页放在**中间**也不得带走整批 |

**这一节能证到哪一步，据实说**：那张核查判据自己的 docstring 逐字写着「**它不证明那些
判据是对的**」——「指向哪里」可执行，「说得准不准」只能靠人读。所以本节的结论是：
八条对照**各自有在盘上的执行器**，且那十六个执行器在本轮全量里**跑绿**（它们所属的
两个纵向文件单独跑也是 17 passed）；至于每一条的措辞是否恰好覆盖了 §G1 那一句的意思、
以及 §G1 那八条是否就是计划者当初想说的八条，**需要人读一遍**，本轮不声称机器已经
替人读过。

## 7. 本轮的边界与自查（哪几处差点说错）

写下来是因为它们比结论更容易被下一个人重犯。

### 7.1 切片 10 的变异检查：六个变异，三个揭示真实缺口

1. **「一条承重判断存在」不等于「它有执行器」。** `owe` 的「没有才写」在三条生产者
   路径上都够不着（上游各有自己的一道闸），端口级的契约判据覆盖不到它，所以它的唯一
   执行器是**新补**的那条直接判据。
2. **两条重放判据的承重点缺失。** 它们停在 `PENDING`，而与「无条件覆盖」同形 ——
   也就是说在真正会出问题的那个形状上，它们判不出来。
3. **裁决侧的原子性没有执行器**（决定、案件、欠账三者同生共死这件事没有判据）。

三条都补了判据，不是登记了事。逐条变异结果见台账「切片 10 · 变异验证」。

**另一条边界**：`test_every_control_names_a_real_executor` **不证明那些判据是对的**
（它自己的 docstring 逐字这么写）。所以 §3 的结论只说「八条各自有在盘上的执行器」，
不说「八条对照已经覆盖」。

### 7.2 两处 docstring 在说假话，是被变异检查发现的

`tests/test_review_store_contract.py` 与 `adapters/memory.py` 两处都声称「把 `owe`
挪到前面，判据会红」—— 实测三遍**都不红**（结构性原因：算欠什么那一步自己会先抛，
或撞同一个键被吸收）。两处都按实测结果改写，并把「位置那一半由谁守」写清。

### 7.3 一个变异可能根本没生效

第一次做「`INSERT OR REPLACE`」变异时，我改的是守卫**之后**的 SQL —— 那是死路径，
于是「变异被守住了」这个结论是假的。发现之后重做成真正生效的形状（守卫去掉 + 先删
后写）才量到真结果。**变异也要先验证它真的改到了执行路径上。**

### 7.4 这一份报告自己抄错过三处，每一处都是核对源码时发现的

| 初稿写了什么 | 盘上是什么 | 处置 |
|---|---|---|
| §3 表重抄了十六个执行器，其中两条（「错国家被标 eligible」「目录别人的邮箱被绑定」）我凭印象写成了别处的判据 | 那两条的执行器逐字住在 `CONTROLS` 里（我写的文件名都存在，但它们不是表里登记的那几条） | **改成不重抄**：只列 `name` 与 `criterion`（逐字），执行器指向源码位置 |
| §4 第 1 行把计划的措辞（YAML / SQL / 复制 CSV / 身份手抄）写成**判据的读数** | 主判据只断言「同一个账号贯穿五处读数」＋「中间没有任何一步是人替它搭的桥」 | 按判据自己的话重写，并把计划那四样的定义、各自的执行器覆盖情况**分开**写 |
| §4 第 5 行写「维护那一路的三格（`REUSED` / `UNCHANGED` / `CHANGED`）」 | 判据里出现的是 `reused` 与 `unchanged` 两种**复核状态**；`CHANGE_SIGNALLED` 是**到期理由**，不是复核状态 | 按判据的四步重写，并把两个外部账（抓取次数 / 盘上新增）与回执三者的关系写清 |

**共同点**：三处都不是判断错，而是**转写错** —— 把上一段上下文的摘要当成了盘上的原话。
所以这一份报告里的每一句引用，**要么逐字核对过，要么不写**。
