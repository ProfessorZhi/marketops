# 巴黎长调研复测：预算与队列仍可用，会话提前结束

日期：2026-10-22；本地时间为 Asia/Shanghai。被评估插件：**0.5.11-rc1**，源码参考 `05c6b51702ed8a7e55c88859b78a8975963db81b`。

**结论：持续执行验收失败。** 研究会话停止时，队列仍有 70 个待处理目标，金额预算约剩 $1.925672，工具明确返回 `continuation_required=true`。会话将低命中率试验后的“停止这一方法”落实为导出检查点并结束，没有执行下一种研究方法。本次没有证明完整巴黎场馆名录或联系人目标已完成。

这是在旧 Run 上续接的一次事后观察，复用了历史材料、候选与账户账本；不是与前一日两组实验条件一致的新 A/B 测试。本次维护诊断只读会话与已有账本、状态和交付清单，未重新跑巴黎研究，未发起新的供应商查询；诊断反馈笔记单独留存在本地。

## 停止路径

1. 首轮生成多个候选检查点；其中一次批量导入遇到身份映射冲突。最后报告仍明确全量和联系人目标未完成。
2. 用户回答产品或服务“其他或暂不限定”，会话继续，并通过分组查询和地址映射把首批 100 个官方 gymnase 安装点导入候选池。早先映射冲突不再能解释最终停止。
3. 会话对约 30 个候选执行联系人试验，没有获得符合要求的个人邮箱；其笔记声明停止这条低效方法。
4. 随后调用 `marketops_handoff(mode="auto")`、反馈打包和余额查看，给出最终答复。没有继续其他联系人来源或完成剩余分页。
5. 停止后复核：70 pending，0 claimed，0 后台在运行批次，0 等待最终落盘结果；`execution.state=CHECKPOINT_CONTINUE_RESEARCH`，`is_final=false`，`continuation_required=true`。

停止低效方法本身合理；问题是未换方法继续。队列没有因为保存工作簿而在后台自动消化。工具可以保存进度并提示下一步，但这些回执没有阻止宿主结束当前回合，也没有建立结束后的自动唤醒。

## Crawl4AI 与预算

最后一回合 Crawl4AI 事件中，**37 次成功、16 次 HOLD、1 次派发前阻止**。HOLD 分布为：8 次 `LOCAL_CRAWL_FAILED`、4 次重定向拒绝、3 次来源访问阻止、1 次反爬启发式阻止；派发前阻止为参数不允许。具体页面存在失败，但不能据此说本地读取器整体失效。账本中的 `SETTLED` 是金额处理状态，不能全部解释成成功读取。

金额模式已生效，历史请求计数上限未启用；免费本地 Crawl4AI 预算为 $0。停止后授权内部预算剩余约 **$1.925672**，其中包括信用额度的估值和未决费用预留，不等于供应商最终现金账单。此次未因授权总预算耗尽而结束，不应通过扩大预算或重置账本来解决。

## 实际产出与覆盖缺口

会话最终自报 48 个有来源支持的室内场馆候选和 3 位具名个人邮箱候选；此次诊断未重新逐条审计这些业务事实，不将其升级为独立核验成果或新发现数量。3 位是该续接 Run 报告的候选总数，不是最后一回合新增 3 位。

停止后池中共 129 个目标：5 done、54 hold、70 pending；另外组织研究评估为 23 个目标、22 HOLD、1 pending，23 个组织仍缺指定岗位覆盖。池路线统计包含通用路线，`hit_rate=0.085` 不能当作个人邮箱命中率。会话最终报告“30 个试验无个人邮箱”与全池路线命中率使用不同分母和准入条件。

官方查询发现的 2,591 条 gymnase **设备记录**只是会话引用的来源规模，不等于独立场馆数，更不表示已导入或核验 2,591 家场馆。本次没有重新审计该数据源全集。
