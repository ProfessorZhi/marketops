## 一、这一片判的是哪四句话

收口矩阵（`docs/B17_ACCEPTANCE_MATRIX_2026-09-28.md`）里，条件 1 有三条缺口、
条件 3 后半有一条，四条都写着「归 B17」而在 e4 结束时**仍然开着**：

1. **「连续两个 Run」零判据** —— 所有「提交两次」的用例都用**同一个键**，盘上只有一行。
2. **它读不到「第一轮已沉淀的事实」** —— `plan_increment` 的七个形参里没有一格是
   「上一轮的产出」。
3. **「不重复池子」零判据**；「不重复成本」只有**账本层**判据，没有一条经过 `submit_run`。
4. **「manual 完成后保持 idle」没有行为判据，且当时不可能有** —— 它要先能结束一轮。

第 4 条在 e4 之后才有主语（结束面），第 1、3 条也是同一件事的下游：一轮能开始、能结束，
「两轮之间」才成为一个可以拿两个 Run 去问的问题。

**这一片补的是判据，不是机制**：`tests/test_mcp_runs.py` 新开第 10 节
（`:3016-3305`），四条端到端判据全部走 `_drive`（真的 MCP 调用），一次不改 `marketops/`。

## 二、「复用第一轮已沉淀的事实」今天读作什么

第 2 条**没有**被补齐，而这一点必须写在最前面，否则这一片会被读成「条件 1 关了」。

冻结的设计记录（`docs/B17_DESIGN_SLICES_2026-09-28.md:1127`）逐字裁定过：

> **没有"连续两轮"的端到端判据**（单轮：先摆账本再算一次）；**"第一轮"在结构上没有
> 对应物**（`Observation` 无 `run_id`、`RunDelta` 不带轮次来源），所以"复用第一轮的沉淀"
> 实际是"复用整个工作区账本此刻的沉淀"；无发起第二轮的调用者。

第 10 节因此**不假装**它判得动「第二轮复用了第一轮记下的那一格」—— 那句话今天读不了。
它改判这一层**实际在做**的那件事，而那句话是判得动的：

> **读数由账决定，不由轮次决定。**

判法是：拿**两个不同**的 Run 去读**同一本**账，比两份读数是否**逐字**相同
（`tests/test_mcp_runs.py:3101`）。这一句在报告上的含义是具体的 —— 一个「让第二轮少读
一部分账」的实现会被它抓住，而那个实现正是「复用第一轮」这句话最容易被误读成的样子。

「哪一轮记了哪一格」要等它落盘才谈得上 —— 那是条件 7 的正面问题
（`application/run_increment.py` 第七节逐字：本片不为它猜一个形状）。

## 三、四条判据各自判什么

| 判据 | 位置 | 判法 | 它钉住的是 |
|---|---|---|---|
| 第二轮读的是账，不是第一轮 | `tests/test_mcp_runs.py:3101` | 两个键受理出**两行**（`:3165`）；两次读数取在**两个不同的 Run** 上（`:3174`），`cells` / `counts` / `inputs` **逐字相同** | 读数只由账本此刻的样子决定 |
| 结束一轮不自行开下一轮 | `:3180` | 先断言那份散文建议**确实写下来了**（`:3223`），再断言盘上仍只有**一行**（`:3224`） | 结束本身也不顺手提一个 |
| 同键重发不重复池子 | `:3227` | 数**两本账**（`_streams`），重发前后归一化后逐字不变（`:3269`、`:3274`） | 幂等做在**池子**上，不只做在 Run 那一行 |
| 受理不写预算账本 | `:3278` | 三次受理之后 `budget_reservation` **零行**（`:3301`、`:3303`、`:3305`） | 「不重复成本」在 `submit_run` 这条面上的落点 |

两处判法值得单独说：

* **第一轮必须真的结束过**（走 `CLOSE` 的两道对账闸，而不是夹具直接 `stop`）。判据要说
  的是「一轮结束之后，这份读数照旧」，没结束的那一份答不了这后半句。
* **判据 3 数的是两本账，不是一行。** 池子那一行是 **upsert** —— 一个把幂等做在 Run 那一
  行、却让第二轮照跑一遍的实现，池子那一行在报告上**看起来还是那一行**，多出来的是**账上
  的第二笔**。所以 `_streams` 把「折入账本身」与「折进去的那几行」**分开报**：一个零、
  一个非零，与「真的折了一行」在合计数上同形。

## 四、`counts` 四档，以及「零档不能省」

判据 1 的第一版断言写错了，错法值得记下来：

```python
assert while_running["counts"] == {REUSE: 6, MISSING: 1}   # 红
```

实际返回是**四档**（`{'reuse': 6, 'new': 0, 'missing': 1, 'expired': 0}`）。改法是**把
两档也写出来**，而不是放宽成「包含」——理由写在判据里：

> `counts` 的承诺就是四档都在，缺的那一档是 0 —— 一条把零档省掉的实现会让「这一档没有」
> 与「这一档是零」同形。

这与 `RunDelta` 九格、`fold_claim` 两本账是同一条纪律的另一处落点。

## 五、变异控制 5/5，其中一条的**第一版**是错的控制

五条变异各自对着一条判据，全部 `exit == 1` 且红名单非空。读数在
`ARTIFACTS_ROOT/work-items/marketops/TARGET-CONVERGENCE-B17/mutation/e5/`（`e5-mutation-v1.txt`
与 `e5-mutation-v2.txt`）。

| 变异 | 目标判据 | 结果 |
|---|---|---|
| M1 `get_run_increment` 只复用本轮开始之后的沉淀（`one.observed_at > run.created_at`） | 判据 1 | KILLED，红 **1** 条，恰好是它 |
| M2 `close_run` 结束后自行受理下一轮 | 判据 2 前半 | KILLED，红 4 条（含它） |
| M3 `recommendations` 非空时自行受理下一轮 | 判据 2 后半 | KILLED，红 **1** 条，恰好是它 |
| M4 `submit_run` 把幂等键换成每次都不一样的 | 判据 3 | KILLED，红 8 条（含它） |
| M5 `submit_run` 受理时无条件预留一笔 | 判据 4 | KILLED，红 **1** 条，恰好是它 |

**M4 的第一版是错的控制，两版都留着。** 第一版把它写成「给幂等键加一个**固定**后缀」
（`+ "-x"`）：它跑出 `exit=1`、红 3 条，看上去是 KILLED —— 但**红名单里没有判据 3**，
也就是说它根本没控制到本片要控制的那一条。原因是一个固定后缀**仍然是个函数**：同一个键
重发两次照样映到同一个键，于是第二轮拿回的仍是第一行，判据 3 的核心断言照样绿。它杀掉的
是一条受理判据与两条空键判据 —— 那是**别的判据在判事**。

真正取消幂等的形态是让键**每次都不一样**（`f"{idempotency_key}-{utc_now()}"`）—— 那才是
「没把调用方的键当键」。第二版据此改，红 8 条，判据 3 在里面。

**这条纪律的推论**：「`exit == 1` 且红名单非空」是必要条件，**不是充分条件** —— 还要问一句
「红的这几条里，有没有我这一条」。

**本片引的行号也过了同一道关**：第 10 节与补记 C 里引的每一个行号都进了
`B17-MATRIX-CITATION-CHECK.py` 的核对表，实测 **20 条全命中**。同一趟跑出 `共 159 条，
MISS 44 条`，那 44 条**全部**是本片之前就有的漂移（判据：本片对被核文件只增不删 ——
`292/0` 与 `27/0`，所以第 10 节落在文件末尾不可能移动上面任何一行的行号）。那 44 条不在
本片重算，理由登记在补记 C 里。

## 六、探针：这条链今天通到哪

`ARTIFACTS_ROOT/work-items/marketops/TARGET-CONVERGENCE-B17/probe/e5-chain/probe.py`（非产物、
不进仓库）七步逐段打印回执，输在 `probe-out.txt`。读数：

1. 受理第一轮 → 盘上 **1** 行。
2. 往维护账记一条观测 → **1** 条。
3. 折一行进池子 → 两本账 **`(1, 1)`**。
4. 结束第一轮 → 回执 **20** 格，**没有** `folds`（e4 已定：读回面才报它）。
5. 受理第二轮（另一个键）→ 盘上 **2** 行，两个 id 不同。
6. 第二轮读增量 → `inputs = {'observations': 1, 'signals': 0}`，
   `counts = {'reuse': 0, 'new': 6, 'missing': 1, 'expired': 0}`，`run_id` 读回就是第二轮。
7. 同键重发第一轮 → **不报错**，盘上无变化（`(2, (1, 1))` → `(2, (1, 1))`）。

**第 6 步那两个数与判据 1 里的不同**（判据 1 是 `reuse: 6 / missing: 1`），而两者互相
印证、不矛盾：探针只记了**一面**观测（`_observe` 的缺省 `aspect` 是 `SOURCE_COVERAGE`），
其余六面从没看过 ⇒ `NEW`；判据 1 用 `_settle_every_face` 把**七面**都记过 ⇒ 那六面
`REUSE`，而 `SOURCE_COVERAGE` 在两种情形下都是 `MISSING`（库里一条证据都没有）。
**同一格 `SOURCE_COVERAGE` 在两次读数里一样，差的是另外六面有没有观测** —— 这正好是
`REUSE` 与 `NEW` 的分界：前者要「看过且窗口未到」，后者是「从没看过」。
